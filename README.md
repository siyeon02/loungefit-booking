# 라운지핏 회원·수업 예약 플랫폼

**🔗 라이브 데모**: https://loungefit-booking-production.up.railway.app
**🔗 관리자 페이지**: https://loungefit-booking-production.up.railway.app/admin (비밀번호:ADMIN_PASSWORD)

필라테스·요가 스튜디오 체인 라운지핏(지점 3곳, 회원 약 1,200명)을 위한 회원 예약 + 횟수제 이용권 자동 관리 시스템입니다. 고객(운영이사 정유나)과의 상담을 바탕으로 설계했습니다.

## 기능
- 회원용 예약 페이지(`/`): 전화번호+이름 본인확인 로그인, 지점별 수업 목록 조회, 예약/취소, 잔여 이용권 확인
- **중복 예약 방지**: 같은 시간대에 겹치는 다른 예약이 있으면 차단 (지점 무관)
- **이용권 자동 차감/환급**: 예약 시 자동 차감, 취소 시 자동 환급 — 수기 계산 오류 문제 해결
- **정원 관리**: 정원 초과 시 예약 불가, 트랜잭션으로 동시 예약 레이스 컨디션 방지
- 관리자 페이지(`/admin`): 회원 등록 및 이용권 부여, 수업 등록, 예약 현황·출석/노쇼 처리

## 로컬 실행 방법
```bash
npm install
cp .env.example .env   # 값 채우기
npx prisma db push
npm run dev
```
`http://localhost:3000`에서 회원 화면, `/admin`에서 관리자 화면.

## Railway 배포 절차
1. Railway 새 프로젝트 생성 → GitHub 저장소 연결
2. PostgreSQL 플러그인 추가 (`DATABASE_URL` 자동 주입)
3. 환경변수 추가: `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`
4. Railway가 `npm run build`(`prisma generate` + `next build`)로 빌드하고, 컨테이너 시작 시 `npm start`(`prisma db push` + `next start`)로 스키마 동기화 후 기동 (Railway 빌드 환경은 DB 내부망에 접근할 수 없어 DB 작업을 런타임으로 분리)
5. Settings → Networking → Generate Domain으로 공개 URL 발급
6. `/admin` 최초 접속 시 지점 3곳(강남점/성수점/홍대점)이 자동 생성됩니다 (상담에서 언급된 지점 수 기준)

## 핵심 의사결정 요약
- **회원 인증 방식**: 별도 비밀번호/앱스토어 가입 없이 "전화번호+이름" 본인확인으로 로그인합니다. 신규 회원은 지점 데스크에서 관리자가 직접 등록하는 구조라(오프라인 등록이 자연스러운 소규모 스튜디오 운영 방식), 온라인 자체 가입 절차를 생략해 오늘 배포 가능한 범위로 스코프를 좁혔습니다.
- **이용권 결제 연동 없음**: 상담에서 "이용권 자동 관리"가 핵심 pain point였고 결제 자체는 별도 요구사항이 아니었기 때문에, 관리자가 회원별로 이용권을 직접 부여하는 방식으로 구현했습니다. 온라인 결제(카드사 PG 연동)는 실제 계약 시 별도 개발 범위로 안내가 필요합니다.
- **중복 예약 방지 로직**: "지점이 다르더라도 같은 시간에 두 수업을 들을 수 없다"는 현실적 제약을 반영해, 예약 시 회원의 기존 BOOKED 예약과 시간대가 겹치는지 검사합니다. 정원 확인과 함께 하나의 DB 트랜잭션으로 묶어 동시 예약 시 레이스 컨디션(정원 초과 등록)을 방지했습니다.
- **노쇼 정책**: 노쇼로 처리된 예약은 이용권 횟수를 환급하지 않습니다 (이미 자리를 차지했으므로). 반면 예약 취소와 관리자의 직접 취소는 횟수를 환급합니다 — 상담에서 언급된 "노쇼가 잦다"는 문제를 이용권 소진 정책으로 자연스럽게 억제하기 위한 설계입니다.
- **지점 관리**: 지점 CRUD를 최소화하고 관리자 최초 접속 시 상담에서 확인된 3개 지점을 자동 시드하도록 했습니다. 필요 시 API로 지점 추가는 가능합니다.
